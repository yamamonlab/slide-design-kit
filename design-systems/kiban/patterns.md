# パターンの一覧

1枚の組み方の一覧。見た目は各デザインシステムが当てる。どれを使うかは型（`types.md`）が決めるので、ここから自由に選ばない。見本は実際のデッキのスライドで、Slides 形式の書き方は `charts.md` と、そのパターンを持つシステムの見本（各システムの `slides.md`）にある。

## 正式なパターン

| パターン | 何を見せるか | 使う型 | 見本 |
|---|---|---|---|
| 要旨（結果3＋構造3） | 上に結果のカード3枚、下に関係を示す数字3つ、最後に論点の帯 | 分析・報告、解説・勉強会 | （公開できる見本なし） |
| 差を矢印で見せる棒グラフ | 前期・計画との差を、破線と強調色の矢印で | 分析・報告 | （公開できる見本なし） |
| 2系列の棒グラフ | 2つの量の関係の推移（利益と利払いなど） | 分析・報告、解説・勉強会 | （公開できる見本なし） |
| 滝グラフ | お金・量の出入りと残り | 分析・報告、解説・勉強会、提案 | （公開できる見本なし） |
| 段階の流れ | 数字が生まれるまでの段階。律速の段を強調 | 分析・報告、解説・勉強会、提案、登壇LT | （公開できる見本なし） |
| パネルの流れ | 2〜4つの段階を矢印でつなぎ、各段の下端に「何が残るか」を帯で | 解説・勉強会、提案 | [X のおすすめ欄 2枚目](../../samples/x-algorithm/)、[X のおすすめ欄 6枚目](../../samples/x-algorithm/) |

| 結論の1文 | 何を決めてほしいかを、3つの要素（パネル）とお願いの帯で | 提案 | （公開できる見本なし） |

見本がまだないパターン（型の欄にだけあるもの）：式、大きな1文、人物と吹き出し、主要指標、持ち帰りの1枚。最初に作ったデッキのスライドを、この表に見本として足す。

## 候補（1回だけ使った形）

デッキを作り終えたときの振り返りで足す。別のデッキで2回目に必要になったら、上の表に昇格させる。

| 形 | 使ったデッキとスライド | なぜ必要だったか |
|---|---|---|
| 会話のイメージ図（人とAI → 成果物） | （公開できる見本なし） | 複数のAIと会話する体験を、機能の説明でなく画面のイメージで見せるため。「イメージ」の注記が必須 |
| 1枚まとめ（ポンチ絵） | （公開できる見本なし） | 官公庁向けに、課題・方向性・内容・効果・予算を1枚に収めるため。このキットには実装なし |
| 段の地図（段の下に工夫を吊るす） | [X のおすすめ欄 8枚目](../../samples/x-algorithm/) | 設計の考え方のように同じ重さの項目が6つ並ぶとき、カードを3×2に並べると文字だけの箱になり、どこに効くか分からなかった。処理の段の真下に吊るすと、効く場所が見える |
| 論点の行（論点｜原資料の記述 → 言えること） | [X のおすすめ欄 10枚目](../../samples/x-algorithm/) | 読むときの注意を3列のパネルにすると中身が少なく空いた。1行1論点にすると、記述から何が言えるかを横に読める |
| 項目と値の行（注意事項） | [X のおすすめ欄 11枚目](../../samples/x-algorithm/) | 注意事項の箇条書きがパネルの上に寄り、下が空いた。項目名と文の行を高さいっぱいに等分した。「出典と注意事項」の中の組み方として、2回目で昇格するか決める |
| 段差の接続（今回 → 次回） | （公開できる見本なし） | 今回の成果が次回の土台になる関係を、高さの差と矢印で見せるため。次回は未確定なので破線 |
| 同心円（自分→周り→組織） | （公開できる見本なし） | 広がる範囲を段階で見せるため。作り直しでは案内の列挙で足りた |
| 線引きの図（任せる／確かめる） | （公開できる見本なし） | 境界の位置を見せるため。2回目だが同じデッキの作り直しなので、別のデッキで使ったら昇格 |
| 発表順の絵 | （公開できる見本なし） | 登壇の順番と持ち時間を、スライド2枚の絵・バケツ・ストップウォッチで見せるため |
| 資金の出どころの流れ | （公開できる見本なし） | 複数の出どころが1つに集まる形 |
| 絵のセット（会場・設備・マイク・時計・カレンダー・紙・スマホ・カメラ・席・ノートPC） | （公開できる見本なし） | 進行・司会の主役。絵なしで作り直すと質が落ちた。2デッキで使ったが同じ会の作り直しなので、別の会で使ったらデザインシステムに取り込む |

## 整理の決まり

- **昇格**：候補の形が、別のデッキで2回目に必要になったら正式なパターンにする。名前、何を見せるか、使う型、見本を書く。
- **外す**：半年どのデッキにも使われなかったパターンは、一覧の最後の「休止」に移す。消さない。
- **数の目安**：1つの型が使うパターンは8個まで。超えたら、型を分けるか、似たパターンをまとめる。
- **システムをまたぐ**：あるシステムで生まれたパターンも、ここでは見た目を除いた「何を見せるか」で書く。実装はそのパターンを使ったシステムだけが持ち、別のシステムで実際に必要になった時に、そのシステムの見た目で組む（`operations.md`「何を共通にするか」）。
