# 新しいデザインシステムを作る手順

毎回この順で作る。手順を飛ばさないことで、どのシステムも基盤の水準から始まる。

## 1. 目録と選び方を見る

`library.md` と `routing.md` を開く。用途の近いシステムがあれば、新しく作らずにそのシステムを改定する。ブランド・主催・イベントが違うだけなら、近いシステムの**変種**にする（`operations.md`「増やし方」）。新しいシステムを作るのは、`routing.md` の問い2でどれにも決まらない主役や場面が、別々のデッキで2回出たときだけ。

## 2. 元の素材を集める

- 実際の資料（スライド・PDF・テンプレート）、ブランドの色と書体、ロゴ・人物などの素材。
- 他人の作品（動画・他社の資料）を参考にするときは、配色・記号・キャラクター・ロゴを写さない。「何が良いか」を言葉にして、自分の形に置き換える。
- 素材がないときは、基盤の既定値から小さく始め、そう明記する。

## 3. 枠を埋める

- README の「ブランドが決める枠」のトークンを、すべてブランドの値にする。名前を変えるときは対応表を書く。
- 書いた色はすべてコントラストを計算する（文字 4.5:1、線と大きな文字 3:1）。届かない組み合わせは使わないか、使い方を限定して README に書く。
- 文字の段・余白は基盤の範囲から選ぶ。

## 4. 違いだけを書く

README は次の雛形で書く。基盤の決まりを書き写さない。

```markdown
**（このシステムを一言で）** （用途・対象・場面を1〜2文）

基盤 Kiban v1.1 に従う。基盤と違う点は下の表のとおり。

## 基盤との違い
| 項目 | 基盤 | このシステム | 理由 |
|---|---|---|---|

## 基盤との対応（トークン名を変えたときだけ）
| 基盤の枠 | このシステムのトークン |
|---|---|

## 語り口 / 色 / 文字 / 形 / 素材 / 部品
（ブランド固有のことだけ）

## 出典とライセンス
```

## 5. 部品と見本

- 繰り返し使う形だけを部品にする（1回しか使わない形は作らない）。
- Slides 形式で使うなら、`charts.md` の見本をブランドの hex に置き換えた版を、そのシステムの章に置く。

## 6. 確かめる

- プレビューをすべて描画し、文字切れ・重なり・空いた余白を見る。
- 試しに3〜8枚のデッキを作り、`deck.md` のチェックリストを通す。
- 表紙（カバー）は最後に作る。

## 7. 目録に登録する

`library.md` の表に1行足す：システム名とリンク、用途・対象、状態、基盤との関係、主な違い。基盤から外れる点があれば「基盤から外れている点」にも書く。
