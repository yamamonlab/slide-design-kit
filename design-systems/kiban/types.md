# デッキの型

デッキは**目的から**作る。最初に「何のための資料か」を決めて型を1つ選び、その型の構成・主役・パターンだけで組む。見た目（色・書体・素材）はデザインシステムが決め、`routing.md` の3つの問いで選ぶ。型は見た目を決めず、どのシステムでも共通。

型を選ぶと、使ってよいパターンが6〜8個に絞られる。一覧（`patterns.md`）から自由に選ぶのではなく、型の欄にあるものから選ぶ。足りないときだけ「その場の形」を作り、作り終えたら記録する（下の「振り返り」）。

## 早見表

| 型 | 目的：見た人に何をしてほしいか | 主役 | 見本 |
|---|---|---|---|
| **分析・報告** | 数字から状況を判断してもらう | 数字とグラフ | [電気は、何でつくられているか](../../samples/denki/)（密図） |
| **解説・勉強会** | 仕組みを理解して、自分で説明できるようにする | 仕組みの図と人物 | [X のおすすめ欄は、どう決まるか](../../samples/x-algorithm/)（Kozu）、[冬の二十四節気](../../samples/sekki/)（和色） |
| **進行・司会** | 場の流れに沿って動いてもらう | 場面の絵（物の線画）・時間軸・人物 | まだない（行動・注意の枚は [地震だ、と思ったら](../../samples/jishin/)（標識）が近い） |
| **提案** | 決めてもらう | 比較と、決めた後の姿 | まだない |
| **登壇LT** | 5〜7分で1つのことを覚えて帰ってもらう | 大きな1文と人物 | [空き家は、900万戸。](../../samples/akiya/)（余白） |

迷ったら：数字を判断させる → 分析・報告。仕組みを分からせる → 解説・勉強会。動いてもらう → 進行・司会。決めてもらう → 提案。短く印象に残す → 登壇LT。

---

## 分析・報告

- **構成**：表紙 → 要旨 → 章ごとに（結果 → 内訳 → 理由）→ 中扉で論点 → 見通し → 支える材料と注意する材料 → 今後の注目点 → 出典。12〜16枚。
- **主役**：数字とグラフ。グラフには必ず図の中の注記を付ける。
- **パターン**：要旨（結果3＋構造3）、差を矢印で見せる棒グラフ、2系列の棒グラフ、滝グラフ、段階の流れ、計画との比較表、対比（支える／注意する）、数字のタイル、論点の中扉、出典と注意事項。
- **使わない**：人物を主役にすること（要旨に1人まで）、物の絵、推奨や売買の判断。
- **注意**：試算は「当資料の計算」と書く。投資家向けは特定の売買を勧めない。

## 解説・勉強会

- **構成**：表紙 → 要旨 → 全体の流れ → 要素ごとの分解（1つずつ）→ 時間差・つまずくところ → 左右する要因 → 出典。6〜10枚。
- **主役**：仕組みの図。人物は「分からない人」「分かった人」の役で1枚に1〜2人。
- **パターン**：要旨、段階の流れ、パネルの流れ、分岐、構成図（アーキテクチャ）、100あたりの行き先（滝グラフ）、時間差の図、2系列の棒グラフ、要因の並び（レバー）、式（人物＋人物＝結果）、出典と注意事項。
- **使わない**：表を主役にすること、物の絵の羅列。

## 進行・司会

- **構成**：開場待機の表紙 → 会場案内 → 主催の紹介 → 本日の流れ → お願い → 登壇者 → 区切りごとの中扉とつなぎ → 締め・次の案内。10〜14枚。
- **主役**：場面の絵。会場・スマホ・マイク・時計・カレンダー・紙などの線画を、1枚に1つの場面として大きく置く。時間軸と人物がそれを支える。文字だけの列挙は主役にしない。
- **絵の決まり**：絵は用意したセットから使い、その場で描かない。絵の中に文字を置かず、ラベルは HTML の文字（24px 以上）で絵の横か上に重ねる。幅や高さが負の図形を入れない。
- **パターン**：開場待機の表紙（スマホ＋QR）、案内の絵解き、時間軸（アイコンつき）、絵つきの3列、登壇者の机、発表順の絵、中扉（時間割つき）、締めの案内。
- **使わない**：グラフ、24px 未満の文字（SVG の中も）、絵のない列挙だけのスライドを続けること。
- **注意**：話す人と話す内容をスピーカーノートに書く（「担当」「話す」「次へ」）。時間は等幅の数字で。
- **QR**：参加してほしい場所（チャットなど）のQRは、表紙・登壇者の紹介・質問を集める枚・締めに置く。投影で読めるよう 150px 以上。出す時機を話に合わせたいときはクリックで出す。
- **訂正（2026-11-17）**：初版に「物の絵なしで成り立つ」と書いたのは誤り。物の絵を使わずに作り直した版は、絵を使った版より情報図としての質が明らかに下がった。進行・司会の型は、場面の絵の出来が質を決める。
- **絵のセット**：このキットには入っていない。作るときは `patterns.md` の候補「絵のセット」を参照。

## 提案

- **構成**：表紙 → 結論（何を決めてほしいか）→ 今の課題（数字で）→ 選択肢の比較 → 推す案の中身 → 進め方と時期 → 費用と効果 → リスクと対策 → お願い。8〜12枚。
- **主役**：比較の表と、決めた後の姿（流れや段階の図）。
- **パターン**：結論の1文、数字のタイル、対比、比較表、段階の流れ、時間軸（進め方）、滝グラフ（費用と効果）、お願いの1枚。
- **使わない**：根拠のない効果の数字。出典か「当資料の試算」を必ず書く。

## 登壇LT

- **構成**：表紙 → つかみの1文 → 自分の状況 → やったこと（2〜3枚）→ 結果 → 持ち帰ってほしい1つ → 締め。6〜9枚。
- **主役**：大きな1文と人物。1枚に言うことは1つで、文字を減らす。
- **パターン**：大きな1文、人物と吹き出し、ビフォーアフター（対比）、段階の流れ、主要指標（大きな数字1つ）、持ち帰りの1枚。
- **使わない**：表、細かいグラフ、本文の段落。

## 振り返り（デッキを作り終えたら必ず）

1. 型のパターンにない「その場の形」を作ったかを確かめる。
2. 作ったなら `patterns.md` の「候補」に1行足す（形の名前、使ったデッキとスライド、なぜ必要だったか）。
3. 同じ形が別のデッキで2回目に必要になったら、正式なパターンに昇格させ、どの型で使うかを決める。
4. 型の構成や主役が合わなかったら、この章の改定として提案する。
