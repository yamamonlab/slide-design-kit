**温白の紙に、黒い枠の構成図。** 1枚全体を1つの図として使うスライド体系。角丸の黒枠パネルを細い矢印でつなぎ、パネルの下端に「何が残るか」を帯で書く。構成図・流れ・画面や会話のイメージが主役の資料に使う。1920×1080（16:9）。

基盤 Kiban v1.1 に従う。基盤と違う点は下の表のとおり。スライドを作る前に、このページと `slides.md`（Slides 形式で写して使う見本）を読む。部品の見た目は `components/<名前>/`。

## 基盤との違い

| 項目 | 基盤 | Kozu | 理由 |
|---|---|---|---|
| 角丸 | 既定は角を立てる | パネル 20px、工程ボックス・帯・吹き出し 14px、アバター 12px | 角丸の黒枠パネルが Kozu の顔。影は使わない |
| タイトル | 64px（48〜64） | 48px・700、左に 12×56px の黒い縦バー | 図に面積を渡すため |
| メッセージライン | 32〜34px・700 | `lead` 32px・**400**、結論の語だけ accent の太字 | 黒い枠の図と太さを競わせない。結論の語は太字で示す |
| 章の表示 | タイトルの上に章番号と章名 | 本文スライドには出さない。章扉（パンくず＋章番号＋題＋線画）で区切る | タイトルの上を空け、図を大きくする |
| 主要指標 | mono 128px | `figure` sans 900・88px、パネルの中 | パネルの中に置くため。等幅書体は使わない（数字は `tabular-nums`） |
| 書体 | 3つまで | Noto Sans JP の1書体（400・700・900） | 構成図は線と面で語り、書体の差は要らない |
| 線の太さ | 規定なし | 3px | 角丸の枠を投影でもはっきり見せる |

## 基盤との対応

名前は基盤の枠と同じ。Kozu が足したトークンだけ書く。

| Kozu のトークン | 役割 |
|---|---|
| `tint` | AIの発言・AIや体験が担う工程の面（Kiban `charts.md`「ノードの意味」の AI） |
| `rule-mid` | 未確定・選ばない案の破線、灰色の矢印 |
| `radius-panel` `radius-node` `radius-avatar` | 角丸の3段 |

## 語り口

- 文体は「である調」か体言止め。表紙・お願いだけ「です・ます調」。
- タイトルは論点を短い名詞句で（「候補の出どころ」「点のつけ方」）。結論・答え・数字の中身をタイトルに書かない。「論点：中身」のようにコロンで答えを足す形も使わない。
- リード文は結論を1〜2文で言い切る（「行動ごとの確率を予測し、重みをかけて足す」）。タイトルだけを順に読むと目次に、リード文だけを順に読むと主張の筋になるようにする。
- 会話・画面のイメージ図には、必ず「会話はあくまでイメージ」のように注記する（作った発言を本物に見せない）。

## 色

- 色はほぼ墨と白。`accent`（マゼンタ）は1枚に1〜2か所：結論の語、焦点の工程ボックスの枠、お願いの枠、章番号、表紙の斜線。
- `tint`（淡い紫）は「AIが話す・AIが担う・体験の時間」にだけ。強調には使わない。
- 選ばない案・これまでのやり方・未確定は、`sunk` の面か `rule-mid` の破線枠で沈める。
- 面の色は `ground`・`surface`・`sunk`・`tint` の4つまで。グラデーション・影は使わない。

## 形

- **パネル**：`surface` に `rule` 3px、角 `radius-panel`。上から 見出し（中央）→ 中身 → 余白 → **下端の帯**。帯は `sunk`、角 `radius-node`、左に線アイコン、右に要点（`label`）。帯は「このパネルから何が残るか」を書く場所。
- **流れ**：パネル同士は 56×28 の細い矢印（線＋開いた矢じり、`rule` 3px）でつなぐ。縦の工程は 28×40 の下向き矢印。左右の対比の間は太字の「»」。
- **工程ボックス**：パネルの中の小さい箱。`surface` に `rule` 3px、角 `radius-node`、名前は 28px・700 中央。焦点は枠を `accent`、AI・体験は面を `tint`、選ばない案は `sunk` 面に `rule-mid` 枠。
- **分岐**：1つの考え（墨塗りのラベル）から3つのパネルへ、直角の線で分ける。
- **会話**：アバター（56px、人は線アイコン、AIは墨塗りに「AI」の文字）＋吹き出し（人は `surface`、AIは `tint`）。AIを顔や体で描かない。
- **時間の帯**：時間の長さに比例した区間の帯（高さ 76px、外枠 `radius-avatar`）。上に括弧でまとまり、下に開始時刻と名前。体験は `ink` 塗り・`tint`、交流は `sunk`。
- **章扉**：左上にパンくず（線＋点＋資料名）、左下寄りに章番号（accent）と題、右に人とAIがつながる抽象の線画（`rule-mid`）。

## 構成図（システム・アーキテクチャ）

仕組みの部品と、その間を何が流れるかを1枚で見せる図。部品の箱（ノード）、実行場所の境目（ゾーン）、直角の線でつくる。パネルの流れ（`PanelFlow`）が「順番」を見せるのに対し、構成図は「どこで・何が・何を渡すか」を見せる。部品は `ArchDiagram`、書き方は `slides.md`「構成図」。見本：[おすすめ欄](../../samples/osusume/) の3枚目。

- **ノードの意味**（面と枠で表す。凡例に使った意味だけ書く）

| 意味 | 見た目 | 例 |
|---|---|---|
| 処理 | `surface` の面、`rule` 3px | 描画、変換、API |
| 置き場 | `sunk` の面 | ファイル、DB、画像、設定 |
| AI | `tint` の面 | エージェント、モデル |
| 外部・人 | `rule-mid` の破線枠（外のゾーンに置く） | 利用者、外部サービス |
| 未確定 | `sunk` の面に `rule-mid` の破線枠、タグ「予定」 | まだ決めていない部品 |
| 焦点 | 枠だけ `accent`（1つまで。AI と重ねてよい） | 説明の要になる部品 |

- **ノードの中身**：上から タグ（`ink` 塗りの小札、24px・700：製品名か種類）→ 名前（28px・700）→ 補足1行（24px、`ink-3`）。高さ 140px（焦点は 160px まで）。タグが名前の言い直しになるなら外す。製品名は実際に使うものだけ。
- **ゾーン**：実行場所・持ち主の境目だけに使う（作業環境、クラウド、社内、外部）。2〜3個。`surface` に `rule` 3px・`radius-panel`、外部のゾーンは `ground` に `rule-mid` の破線。左上にゾーン名（24px・700、`ink-3`）。「渡さない」「見せない」のような情報の切り分けはゾーンにせず、注記で書く。
- **線**：直角だけ（斜め・曲線は使わない）。`rule` 3px、開いた矢じり。1本に1つの向き。行きと戻りは2本に分けて 60px 離す。交差させない（交差しそうならノードを並べ替える）。ラベルは流れる物の名詞（6字まで、24px・700）を線のすぐ上か右に。ラベルのない線は、矢印だけで意味が分かる短い線に限る。
- **読む順**：左上から始め、主な流れは 左→右→下 の時計回り。戻りの流れ（修正・再実行）は下の段を右から左へ。
- **注記**：2種類まで。技術的な補足（24px、`ink-3`）はその部品のすぐ下に。仕組みの要（26px・700、`ink`）は1つだけ、関係する線のすぐ横に。引き出し線は使わない（破線と見分けにくい）。
- **凡例**：図の下に1行（24px、`ink-3`）。使った面と枠の意味だけ。
- **量**：ノード8つ、線10本まで。超えるなら、ゾーン単位の全体図と、ゾーンの中の詳細図の2枚に分ける。Slides の固定要素（1つの箱に24個まで）にも収める。
- **文章**：タイトルは「〜の仕組み」「〜の構成」の名詞句。リード文で流れを1〜2文で言い切る（「描画した画像を、別のエージェントが採点する」）。図の用語とリード文の用語をそろえる。
- **原資料に忠実に**：資料や会話にない部品・通信・製品名を足さない。構成図はもっともらしく見えるぶん、作った線が事実に見える。

## アイコン

- Slides の `x-icon` の線アイコンを `ink` 単色、32px で。必ず語と組で使う（下端の帯、仕様カードの見出し、アバター）。
- 絵文字・塗りのアイコン・ロボットの絵は使わない。

## 選ばれる条件と得意技

Kiban `routing.md` の問い2で「構成図・流れ・画面や会話のイメージ」が主役のとき、Kozu が選ばれる。システムの構成図（アーキテクチャ・データの流れ）もここ。型（`types.md`）は問わない（提案・解説・登壇LT が多いが、構成図が主役なら分析・報告でも使う）。

- **得意技（ほかのシステムへ写さない）**：1枚全体の構成図、システムの構成図（`ArchDiagram`）、段の地図（`StageMap`）、論点の行（`IssueRows`）、項目と値の行（`KeyValueRows`）、パネルの流れと下端の成果物の帯（`PanelFlow`）、会話のイメージ図（`ChatMock`）、時間に比例した帯（`TimeBand`）、章扉（`SectionDivider`）。
- **苦手（別のシステムを選び直す）**：数字のグラフが主役のスライドが続くなら密図。デッキの中で1〜2枚だけグラフが要るなら、Kiban `charts.md` の見本を Kozu の hex で組む（グラフ部品は Kozu に足さない）。
- **借りる素材**：人物の線画が要るときは、CC0 などの再配布できる素材をデッキにコピーして使い、出典を書く。このキットには同梱しない。

## やらないこと

- 片側だけ色の線のカード、上端の色帯、影、グラデーション。
- パネルの中を文字だけで埋める（工程ボックス・会話・数字のどれかを入れる）。
- 1枚に accent を3か所以上。
- 24px 未満の文字。作った数字・発言を本物として載せる。

## 出典とライセンス

- 骨格・文章・読みやすさ：Kiban スライド共通基盤。
- 図の幾何・量の上限・ノードの意味：Kiban `charts.md`。
- 見た目の方向：黒板講義系の図解スタイル（温白の地、黒バーの見出し、角丸の枠を矢印でつなぐ構成図）を参考に、良い点を言葉にして置き換えた。色・書体・部品・決まりはすべてこのシステムで新しく作ったもので、特定のチャンネル・作者・資料の配色・ロゴ・キャラクター・線画は使っていない。特定のチャンネルや作者とは関係がなく、公認も受けていない。
- 見本デッキ：[おすすめ欄は、どう決まるか](../../samples/osusume/)（解説・勉強会型。架空のSNS「ナミマ」を題材にした例）。
