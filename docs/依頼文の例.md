# 依頼文の例

AI（Claude など）にスライドを作ってもらうときの依頼文です。コピーして、`〈 〉` の中を自分の内容に書き換えて使います。

依頼文は「何のための資料か（デッキの型）」から始めます。見た目（デザインシステム）は型では決まりません。選び方は [Kiban の `routing.md`](../design-systems/kiban/routing.md) にあります。

## 先に決めること

| 決めること | 例 |
|---|---|
| デッキの型 | 下の5つから1つ |
| デザインシステム | Kozu・余白・密図・標識・和色から1つ |
| 見る人 | 部署の同僚10人、社外の勉強会の参加者 など |
| 見た人にしてほしいこと | 判断してほしい、仕組みを説明できるようになってほしい など |
| 材料 | 公開されている資料・統計、自分のメモ |
| 枚数 | 型ごとの目安（下の表） |

| 型 | 目的 | 枚数の目安 | 合うデザインシステムの例 |
|---|---|---|---|
| 分析・報告 | 数字から状況を判断してもらう | 12〜16枚 | 密図 |
| 解説・勉強会 | 仕組みを理解して、自分で説明できるようにする | 6〜10枚 | Kozu、和色、標識 |
| 進行・司会 | 場の流れに沿って動いてもらう | 10〜14枚 | 標識 |
| 提案 | 決めてもらう | 8〜12枚 | Kozu、密図 |
| 登壇LT | 5〜7分で1つのことを覚えて帰ってもらう | 6〜9枚 | 余白 |

> つまずきどころ：社外秘の資料、顧客や個人の情報は、AI に渡す前に会社のルールを確かめます。このキットの見本は、公開されている資料だけで作っています。

## 共通の書き出し

どの型でも、この形で送ります。デザインシステムのファイルは渡さず、このリポジトリのファイルの URL 2本を Claude に読ませます。

```text
次のデザインシステムを読んで、その決まりどおりに、下の素材から日本語のスライドを〈5〉枚作ってください。
https://raw.githubusercontent.com/yamamonlab/slide-design-kit/main/design-systems/〈kozu〉/README.md
https://raw.githubusercontent.com/yamamonlab/slide-design-kit/main/design-systems/〈kozu〉/slides.md
〈ここに、下の型ごとの依頼文を入れる〉

【素材】
〈ここに材料を貼る〉
```

| デザインシステム | URL に入れるフォルダ名 |
|---|---|
| Kozu | `kozu` |
| 余白 | `yohaku` |
| 密図 | `mitsuzu` |
| 標識 | `hyoshiki` |
| 和色 | `washoku` |

- URL は `raw.githubusercontent.com` で始まるものを使います。`github.com/...` のページの URL は、Claude が読めません。
- 型ごとの依頼文の「材料」の行は、【素材】の下に材料を貼るなら省いてかまいません。
- 確かめたのは、無料プランで Kozu を使い、5枚を作ったところまでです（2026-11-25）。ほかの4つは**未確認**です。

> つまずきどころ：URL の2行を両方書き換えます。片方だけだと、別のデザインシステムの決まりが混ざります。

## 分析・報告

```text
型は「分析・報告」です。
見る人：〈部署の同僚10人〉。見た人に〈来期の予算配分を判断〉してほしいです。
材料：〈添付の資料名、または公開URL〉
構成は、表紙 → 要旨 → 章ごとに（結果 → 内訳 → 理由）→ 見通し → 支える材料と注意する材料 → 今後の注目点 → 出典、の順で〈12〉枚にしてください。
グラフには、図の中に注記を1〜2つ付けてください。
```

## 解説・勉強会

```text
型は「解説・勉強会」です。
見る人：〈この分野が初めての参加者〉。見た人が〈仕組みを自分で説明できる〉ようにしたいです。
材料：〈添付の資料名、または公開URL〉
構成は、表紙 → 要旨 → 全体の流れ → 要素ごとの分解 → つまずくところ → 左右する要因 → 出典、の順で〈8〉枚にしてください。
本文スライドの3分の1以上を、流れや構成の図にしてください。
```

## 進行・司会

```text
型は「進行・司会」です。
イベント：〈名前、日時、会場〉。参加者に〈当日の流れに沿って動いて〉もらいたいです。
当日の流れ：〈時刻と内容の一覧〉
構成は、開場待機の表紙 → 会場案内 → 本日の流れ → お願い → 登壇者 → 区切りごとの中扉 → 締め・次の案内、の順で〈12〉枚にしてください。
各スライドに、話す人と話す内容をスピーカーノートで書いてください。
```

> つまずきどころ：登壇者の名前・所属を載せるときは、本人と所属先の了承を先にもらいます。

## 提案

```text
型は「提案」です。
見る人：〈決める人〉。〈何を〉決めてほしいです。
材料：〈今の課題の数字、選択肢、費用の見込み〉
構成は、表紙 → 結論（何を決めてほしいか）→ 今の課題（数字で）→ 選択肢の比較 → 推す案の中身 → 進め方と時期 → 費用と効果 → リスクと対策 → お願い、の順で〈10〉枚にしてください。
効果の数字には、出典か「当資料の試算」を書いてください。
```

## 登壇LT

```text
型は「登壇LT」です。持ち時間は〈5〉分です。
見る人に〈1つのこと〉を覚えて帰ってほしいです。
材料：〈自分の体験のメモ、使う数字の出典〉
構成は、表紙 → つかみの1文 → 自分の状況 → やったこと（2〜3枚）→ 結果 → 持ち帰ってほしい1つ → 締め、の順で〈7〉枚にしてください。
1枚に言うことは1つにして、文字を少なくしてください。
```

## 直してもらうとき

```text
〈3〉枚目の文字が枠からはみ出しています。文字を小さくせずに、図の配置を変えて収めてください。
```

```text
タイトルだけを順に読むと、話の筋が通りません。各スライドのタイトルを、そのスライドの論点を表す短い文に直してください。
```

できあがったら、[チェックリスト](チェックリスト.md) で確かめます。
