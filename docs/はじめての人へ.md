# はじめての人へ — デザインシステムを取り込んで、1枚目のスライドを作る

対象：スライドを AI に作ってもらったことがない人、デザインシステムという言葉が初めての人 / 所要：30〜45分 / 最終確認：2026-11-25

このページだけで、最後までたどれるように書いています。道は2つあります。

| 道 | 向いている人 | できあがるもの |
|---|---|---|
| **A. Claude を使う** | Claude（claude.ai）のアカウントがある人 | Claude が作ったスライド（PowerPoint・Googleスライド・PDF に書き出せる） |
| **B. Claude を使わない** | PowerPoint か Googleスライドで自分で作る人 | このキットの色と組み方を写した、自分のスライド |

どちらの道も、手順1〜3は同じです。

> 画面の名前とメニューは、2026年11月時点の Claude の公式ヘルプ（support.claude.com）で確かめたものです。画面は変わることがあります。見当たらないときは、ヘルプで最新の名前を確かめてください。

## 共通の手順

### 1. このキットを手元に保存する

1. このリポジトリのトップページを開く。
2. 緑の **Code** ボタン → **Download ZIP** を押す。
3. ダウンロードした `slide-design-kit-main.zip` をダブルクリックして展開する。

![撮影：GitHub の Code ボタンを開き、Download ZIP が見えている画面](images/todo-01.png)

- **確認ポイント**：展開したフォルダの中に `design-systems` と `samples` と `docs` の3つのフォルダがある。
- **つまずきどころ**：Windows では、ZIP をダブルクリックしただけでは「展開」されていないことがあります。右クリック →「すべて展開」を選びます。

### 2. 見本を見て、デザインシステムを1つ選ぶ

`samples` の中の5つのフォルダに、それぞれ `preview.jpg`（全スライドの一覧画像）があります。開いて見比べ、作りたい資料に一番近いものを1つ選びます。

| 作りたい資料 | 選ぶデザインシステム | フォルダ |
|---|---|---|
| 仕組み・流れ・構成を説明したい | Kozu | `design-systems/kozu` |
| 1つの数字や1文を強く印象に残したい（短い発表） | 余白 | `design-systems/yohaku` |
| たくさんの数字の関係を1枚で見せたい | 密図 | `design-systems/mitsuzu` |
| 行動・手順・注意を伝えたい | 標識 | `design-systems/hyoshiki` |
| 季節・暦・和の題材を扱いたい | 和色 | `design-systems/washoku` |

![撮影：samples/akiya/preview.jpg を開いた画面](images/todo-02.png)

- **確認ポイント**：選んだデザインシステムの名前を1つ言える。
- **つまずきどころ**：迷ったら Kozu を選びます。説明の資料のほとんどに合います。
- `design-systems/kiban`（Kiban）は全部に共通の基盤なので、選ぶ必要はありません。道Aでは一緒に渡します。

### 3. 資料の「型」と材料を決める

作り始める前に、次の3つをメモ帳に書きます。

| 書くこと | 例 |
|---|---|
| デッキの型（[依頼文の例](依頼文の例.md) の5つから1つ） | 解説・勉強会 |
| 見る人と、見た人にしてほしいこと | 部署の新人5人。社内のツールの仕組みを説明できるようになってほしい |
| 材料（公開されている資料・自分のメモ） | ツールの公式ヘルプのURL、自分の説明メモ |

- **確認ポイント**：「誰に、何をしてほしいか」が1文で言える。
- **つまずきどころ**：社外秘の資料や、顧客・個人の情報は、AI に渡す前に会社のルールを確かめます。分からなければ、公開されている情報だけで練習します。

## 道A：Claude を使う

### A-4. プロジェクトを作り、デザインシステムのファイルを入れる

Claude の「プロジェクト」は、ファイルを入れておくと、そのプロジェクトのチャットで毎回読んでくれる場所です。無料プランでも使えます（無料プランは5つまで）。

1. claude.ai を開き、左のメニューから **Projects** を開いて、新しいプロジェクトを作る。名前は「スライド（Kozu）」など。
2. プロジェクトのページの右側にある **project knowledge** の **＋** から、次のファイルを追加する。
   - 手順2で選んだフォルダ（例：`design-systems/kozu`）の `README.md`・`slides.md`・`tokens.json`・`tokens.css`
   - `design-systems/kiban` の `README.md`・`types.md`・`deck.md`
   - 見本のデッキ1本（例：`samples/x-algorithm/source/slides` の中の HTML を2〜3枚）

![撮影：プロジェクトのページで、project knowledge にファイルが並んでいる画面](images/todo-03.png)

- **確認ポイント**：project knowledge に、選んだデザインシステムの `README.md` と Kiban の `README.md` の両方が見える。
- **つまずきどころ**：`README.md` は全部のフォルダにあるので、名前だけでは区別がつきません。追加する前に、ファイル名の前にフォルダ名を付けて（例：`kozu-README.md`）保存し直すと、後で迷いません。

> Pro 以上のプランでは、「Design systems」（デザインシステム）の機能を使って、ファイルからデザインシステムを登録することもできます（ベータ）。設定の **Settings → Capabilities** にある Design systems の **Manage** から開きます。登録すると、プロジェクトをまたいで同じ見た目を使えます。このページでは、どのプランでも使えるプロジェクトの道で説明します。

### A-5. 依頼文を送って、スライドを作ってもらう

プロジェクトの中で新しいチャットを開き、[依頼文の例](依頼文の例.md) から型に合う依頼文をコピーし、`〈 〉` を書き換えて送ります。最初は枚数を3枚にして試すと早く終わります。

![撮影：プロジェクトのチャットに依頼文を貼った画面](images/todo-04.png)

- **確認ポイント**：返ってきたスライドの色・見出しの形が、見本の `preview.jpg` と似ている。
- **つまずきどころ**：見本と見た目が違うときは、「project knowledge の `kozu-README.md` と `slides.md` を読み直して、色と見出しの形を合わせてください」と送ります。

### A-6. 1枚ずつ直してもらう

チェックリストの「2. 読みやすさ」を見ながら、気になるところを1つずつ伝えます。

```text
2枚目の文字が枠からはみ出しています。文字を小さくせずに、図の配置を変えて収めてください。
```

- **確認ポイント**：24px より小さい文字がない、はみ出しがない。
- **つまずきどころ**：一度に5つも6つも直してもらうと、前に直ったところが元に戻ることがあります。1回に1〜2つずつ頼みます。

### A-7. 書き出す

できあがったスライドを、PowerPoint・Googleスライド・PDF のどれかに書き出します。スライドの画面にある書き出し（Export）のメニューから選びます。

![撮影：スライドの書き出しメニューを開いた画面](images/todo-05.png)

- **確認ポイント**：書き出したファイルを開いて、文字が欠けたり重なったりしていない。
- **つまずきどころ**：PowerPoint や Googleスライドで開くと、書体が別のものに置き換わり、文字があふれることがあります。そのときは書き出したファイルの上で直すか、PDF を使います。

→ [チェックリスト](チェックリスト.md) を最後まで通したら完成です。

## 道B：Claude を使わない（PowerPoint・Googleスライド）

このキットの「色・文字の大きさ・余白・組み方」を、自分のスライドに写します。

### B-4. スライドの大きさを 16:9 にする

- PowerPoint：**デザイン → スライドのサイズ → ワイド画面（16:9）**
- Googleスライド：**ファイル → ページ設定 → ワイドスクリーン 16:9**

- **確認ポイント**：スライドが横長（16:9）になっている。
- **つまずきどころ**：このキットの数字は 1920×1080 の大きさで書いてあります。PowerPoint の 16:9 は幅 33.867cm なので、キットの「px」は **ほぼ 半分の数字を pt（ポイント）として**読みます（例：48px → 24pt、24px → 12pt）。

### B-5. 色を写す

選んだデザインシステムの `tokens.css` をメモ帳（テキストエディタ）で開きます。`--ground: #f7f6f2;` のような行が、色の名前と値です。

| 名前 | 使うところ |
|---|---|
| `ground` | スライドの背景 |
| `ink` | 見出しと主な文字 |
| `ink-2` | 本文 |
| `ink-3` | 注記・出典・ページ番号 |
| `accent` | 強調の色（1枚に2か所まで） |

`#` から始まる6文字を、PowerPoint・Googleスライドの色の指定（「その他の色」→ 16進数／カスタム）に入力します。

![撮影：PowerPoint の色の設定で 16進数を入力している画面](images/todo-06.png)

- **確認ポイント**：背景・見出し・本文・強調の4色が、見本の `preview.jpg` と同じに見える。
- **つまずきどころ**：和色・密図・標識・余白では、名前が `ink-mute` や `signal` などになっています。各フォルダの `README.md` の「色」の節に、何に使う色かが書いてあります。

### B-6. 文字の大きさと書体を決める

- 書体：Noto Sans JP（和色の見出しは Noto Serif JP）。Google Fonts から無料で入れられます。入れられないときは、游ゴシック・メイリオで代わりにします。
- 大きさ：`README.md` の「基盤との違い」の表と `tokens.css` の `--text-` で始まる行を見ます。例：`--text-title: 700 48px/1.25 …` は「太字・48px（PowerPoint では 24pt）」。
- どの文字も 24px（12pt）より小さくしません。

- **確認ポイント**：タイトル・本文・出典の3つの大きさが決まっている。
- **つまずきどころ**：Googleスライドでは、Noto Sans JP は「フォント → その他のフォント」から追加します。

### B-7. 1枚目を作る

見本のデッキの `preview.jpg` から、まねしたいスライドを1枚選び、同じ配置で作ります。

1. 上にタイトル（そのスライドの論点を短い文で）。
2. その下に結論の1文。
3. 真ん中に図か数字（本文の文章を並べるより、図を1つ）。
4. 左下に出典、右下にページ番号。

![撮影：見本と並べて、自分のスライドの1枚目を作っている画面](images/todo-07.png)

- **確認ポイント**：タイトルだけを読んで、そのスライドで何を言いたいかが分かる。
- **つまずきどころ**：文字をたくさん書きたくなったら、2枚に分けます。1枚で言うことは1つです。
