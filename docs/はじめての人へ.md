# はじめての人へ — デザインシステムを URL で読ませて、1枚目のスライドを作る

対象：スライドを AI に作ってもらったことがない人、デザインシステムという言葉が初めての人 / 所要：30〜45分 / 最終確認：2026-11-25

このページだけで、最後までたどれるように書いています。道は2つあります。

| 道 | 向いている人 | できあがるもの |
|---|---|---|
| **A. Claude を使う** | Claude（claude.ai）のアカウントがある人 | Claude が作ったスライド（PowerPoint・Googleスライド・PDF に書き出せる） |
| **B. Claude を使わない** | PowerPoint か Googleスライドで自分で作る人 | このキットの色と組み方を写した、自分のスライド |

どちらの道も、手順1〜2は同じです。ファイルのダウンロードやアップロードは要りません。このリポジトリはブラウザで開いて見るだけで使えます。

> 画面の名前とメニューは、2026年11月時点の Claude の公式ヘルプ（support.claude.com）で確かめたものです。公式ヘルプで確かめられなかったものには「未確認」と書いています。画面は変わることがあります。見当たらないときは、ヘルプで最新の名前を確かめてください。

## 共通の手順

### 1. 見本を見て、デザインシステムを1つ選ぶ

このリポジトリのトップページ（README）に、5つの見本のスライドの一覧画像が並んでいます。見比べて、作りたい資料に一番近いものを1つ選びます。画像を押すと、見本のフォルダが開きます。

| 作りたい資料 | 選ぶデザインシステム | フォルダ名 | 見本のフォルダ名 |
|---|---|---|---|
| 仕組み・流れ・構成を説明したい | Kozu | `kozu` | `osusume` |
| 1つの数字や1文を強く印象に残したい（短い発表） | 余白 | `yohaku` | `akiya` |
| たくさんの数字の関係を1枚で見せたい | 密図 | `mitsuzu` | `denki` |
| 行動・手順・注意を伝えたい | 標識 | `hyoshiki` | `jishin` |
| 季節・暦・和の題材を扱いたい | 和色 | `washoku` | `sekki` |

![撮影：このリポジトリのトップページで、見本の一覧画像が並んでいる画面](images/todo-01.png)

- **確認ポイント**：選んだデザインシステムの名前と、表のフォルダ名を言える。
- **つまずきどころ**：迷ったら Kozu を選びます。説明の資料のほとんどに合います。
- `design-systems/kiban`（Kiban）は全部に共通の基盤なので、選ぶ必要はありません。道Aでは依頼文で一緒に読ませます。

### 2. 資料の「型」と材料を決める

作り始める前に、次の3つをメモ帳に書きます。

| 書くこと | 例 |
|---|---|
| デッキの型（[依頼文の例](依頼文の例.md) の5つから1つ） | 解説・勉強会 |
| 見る人と、見た人にしてほしいこと | 部署の新人5人。社内のツールの仕組みを説明できるようになってほしい |
| 材料（公開されている資料・自分のメモ） | ツールの公式ヘルプのURL、自分の説明メモ |

- **確認ポイント**：「誰に、何をしてほしいか」が1文で言える。
- **つまずきどころ**：社外秘の資料や、顧客・個人の情報は、AI に渡す前に会社のルールを確かめます。分からなければ、公開されている情報だけで練習します。

## 道A：Claude を使う

デザインシステムのファイルは、Claude に渡しません。依頼文の中に、このリポジトリのファイルの URL を2本書いて、Claude に読ませます。どのプランでも同じ手順です。

### A-3. 新しいチャットで、URL を入れた依頼文を送る

1. claude.ai を開き、新しいチャットを開く。
2. 次の形で依頼文を書いて送る。1行目は頼むこと、2〜3行目は手順1で選んだデザインシステムの URL 2本、その後ろに【素材】です。最初は枚数を3枚にして試すと早く終わります。

Kozu を選んだときは、次のとおりです。`〈 〉` を書き換えます。

```text
次のデザインシステムを読んで、その決まりどおりに、下の素材から日本語のスライドを〈5〉枚作ってください。
https://raw.githubusercontent.com/yamamonlab/slide-design-kit/main/design-systems/kozu/README.md
https://raw.githubusercontent.com/yamamonlab/slide-design-kit/main/design-systems/kozu/slides.md

【素材】
〈ここに材料を貼る〉
```

ほかのデザインシステムを選んだときは、URL の `kozu` を手順1の表のフォルダ名に置き換えます。型ごとの書き足し方は [依頼文の例](依頼文の例.md) にあります。

![撮影：チャットに URL 入りの依頼文を貼った画面](images/todo-02.png)

- **確認ポイント**：返ってきたスライドの色・見出しの形が、見本の一覧画像と似ている。
- **つまずきどころ**：
  - URL は `raw.githubusercontent.com` で始まるものを使います。`github.com/...` のページの URL では、Claude が読めずに、ふつうのデザインで作られてしまいます。
  - 見本と見た目が違うときは、「依頼文の URL の README と slides.md を読み直して、色と見出しの形を合わせてください」と送ります。
  - 「ページを開けなかった」と返ってきたら、URL が途中で切れていないかを見ます。Claude は、ウェブ検索がオンのときに URL のページを読めます。入力欄のメニューで **Web search**（ウェブ検索）がオンかを確かめます。Team・Enterprise プランでは、管理者が組織の設定の **Capabilities** で許可していないとオンにできません。
  - 別のチャットで作り直すときも、依頼文の URL の2行を消さずに付けます。
  - 確かめたのは、無料プランで Kozu を使い、5枚を作ったところまでです（2026-11-25）。ほかの4つのデザインシステムは、同じ形で動くかを**未確認**です。

> Pro 以上のプランでは、「Design systems」（デザインシステム）の機能を使って、デザインシステムを登録することもできます（ベータ）。設定の **Settings → Capabilities** にある Design systems の **Manage** から開きます。登録すると、毎回 URL を書かなくても同じ見た目を使えます。このページでは、どのプランでも使える URL の道で説明します。

### A-4. 1枚ずつ直してもらう

チェックリストの「2. 読みやすさ」を見ながら、気になるところを1つずつ伝えます。

```text
2枚目の文字が枠からはみ出しています。文字を小さくせずに、図の配置を変えて収めてください。
```

- **確認ポイント**：24px より小さい文字がない、はみ出しがない。
- **つまずきどころ**：一度に5つも6つも直してもらうと、前に直ったところが元に戻ることがあります。1回に1〜2つずつ頼みます。

### A-5. 書き出す

できあがったスライドを、PowerPoint・Googleスライド・PDF のどれかに書き出します。スライドの画面にある書き出し（Export）のメニューから選びます。

![撮影：スライドの書き出しメニューを開いた画面](images/todo-03.png)

- **確認ポイント**：書き出したファイルを開いて、文字が欠けたり重なったりしていない。
- 書き出しは、この手順書では**未確認**です。メニューの名前は画面で確かめます。
- **つまずきどころ**：PowerPoint や Googleスライドで開くと、書体が別のものに置き換わり、文字があふれることがあります。そのときは書き出したファイルの上で直すか、PDF を使います。

## 道B：Claude を使わない（PowerPoint・Googleスライド）

このキットの「色・文字の大きさ・余白・組み方」を、自分のスライドに写します。

### B-3. スライドの大きさを 16:9 にする

- PowerPoint：**デザイン → スライドのサイズ → ワイド画面（16:9）**
- Googleスライド：**ファイル → ページ設定 → ワイドスクリーン 16:9**

- **確認ポイント**：スライドが横長（16:9）になっている。
- **つまずきどころ**：このキットの数字は 1920×1080 の大きさで書いてあります。PowerPoint の 16:9 は幅 33.867cm なので、キットの「px」は **ほぼ 半分の数字を pt（ポイント）として**読みます（例：48px → 24pt、24px → 12pt）。

### B-4. 色を写す

このリポジトリのページで、選んだデザインシステムのフォルダ（例：`design-systems/kozu`）を開き、`tokens.css` を押して中身を表示します。ダウンロードは要りません。`--ground: #f7f6f2;` のような行が、色の名前と値です。

| 名前 | 使うところ |
|---|---|
| `ground` | スライドの背景 |
| `ink` | 見出しと主な文字 |
| `ink-2` | 本文 |
| `ink-3` | 注記・出典・ページ番号 |
| `accent` | 強調の色（1枚に2か所まで） |

`#` から始まる6文字を、PowerPoint・Googleスライドの色の指定（「その他の色」→ 16進数／カスタム）に入力します。

![撮影：PowerPoint の色の設定で 16進数を入力している画面](images/todo-04.png)

- **確認ポイント**：背景・見出し・本文・強調の4色が、見本の一覧画像と同じに見える。
- **つまずきどころ**：和色・密図・標識・余白では、名前が `ink-mute` や `signal` などになっています。各フォルダの `README.md` の「色」の節に、何に使う色かが書いてあります。

### B-5. 文字の大きさと書体を決める

- 書体：Noto Sans JP（和色の見出しは Noto Serif JP）。Google Fonts から無料で入れられます。入れられないときは、游ゴシック・メイリオで代わりにします。
- 大きさ：`README.md` の「基盤との違い」の表と `tokens.css` の `--text-` で始まる行を見ます。例：`--text-title: 700 48px/1.25 …` は「太字・48px（PowerPoint では 24pt）」。
- どの文字も 24px（12pt）より小さくしません。

- **確認ポイント**：タイトル・本文・出典の3つの大きさが決まっている。
- **つまずきどころ**：Googleスライドでは、Noto Sans JP は「フォント → その他のフォント」から追加します。

### B-6. 1枚目を作る

見本の一覧画像（各見本のフォルダの `preview.jpg`）から、まねしたいスライドを1枚選び、同じ配置で作ります。

1. 上にタイトル（そのスライドの論点を短い文で）。
2. その下に結論の1文。
3. 真ん中に図か数字（本文の文章を並べるより、図を1つ）。
4. 左下に出典、右下にページ番号。

![撮影：見本と並べて、自分のスライドの1枚目を作っている画面](images/todo-05.png)

- **確認ポイント**：タイトルだけを読んで、そのスライドで何を言いたいかが分かる。
- **つまずきどころ**：文字をたくさん書きたくなったら、2枚に分けます。1枚で言うことは1つです。
