# できあがったスライドのチェックリスト

スライドができたら、発表や配布の前にこの順で確かめます。AI に作ってもらったスライドでも、自分で作ったスライドでも同じです。もとになっている決まりは [Kiban の `deck.md`](../design-systems/kiban/deck.md) にあります。

## 1. 話の筋（5分）

- [ ] **タイトルだけ**を1枚目から順に読んで、話の流れが通る
- [ ] **各スライドの結論の1文（メッセージ）だけ**を順に読んで、言いたいことが伝わる
- [ ] 1枚で言っていることが1つになっている。2つあるなら2枚に分ける
- [ ] 最初に選んだ「デッキの型」（[依頼文の例](依頼文の例.md)）と、構成が合っている

> つまずきどころ：タイトルが「現状」「課題」のような1語だと、タイトルだけでは筋が通りません。「空き家は30年で約2倍」のように、そのスライドの論点を書きます。

## 2. 読みやすさ（1枚ずつ）

- [ ] 24px より小さい文字がない（スライドの大きさ 1920×1080 のとき。図の中の文字も含む）
- [ ] 文字と背景の色の差が十分ある（薄い灰色の文字を本文に使っていない）
- [ ] 色だけで意味を伝えていない。良い・悪いには ▲▼ や「増加」などの語を添えている
- [ ] 強調の色は1枚に2か所まで
- [ ] 文字が枠からはみ出していない。重なっていない
- [ ] 下の3割以上が空いたスライドがない（空いたら図を大きくする。文字を大きくして埋めない）

> つまずきどころ：パソコンの画面では読めても、会場の後ろの席からは読めないことがあります。実際に投影するか、画面から2〜3m離れて見ます。

## 3. 数字と出典

- [ ] 数字に単位と、何と比べているか（前年比、計画比など）が書いてある
- [ ] 作った数字・例の数字を、本物のように載せていない。例は「例」と書く
- [ ] 自分で計算した数字には「当資料の計算」、言い換えた文には「当資料の言い換え」と書いてある
- [ ] 出典が「出典：発行者「資料名」（発行年）」の形で、そのスライドの左下にある
- [ ] AI が書いた数字を、元の資料で1つずつ確かめた

> つまずきどころ：AI は出典の資料名や数字をそれらしく作ってしまうことがあります。出典の資料を自分で開き、数字が一致するかを必ず見ます。

## 4. 公開してよいか

- [ ] 社外秘・内部の情報、顧客や個人の情報が入っていない
- [ ] 実在の人の名前・所属は、本人と所属先の了承があるものだけ
- [ ] 写真・絵・図は、使ってよい条件（ライセンス）を確かめ、作者などを書いてある
- [ ] 実在の会社のロゴや画面を、許可なく使っていない

## 5. 最後に実物で

- [ ] PDF や PPTX に書き出したものを開き、文字切れ・重なり・書体の置き換わりがないか見た
- [ ] 発表する場所の画面（またはプロジェクター）で1回映した

> つまずきどころ：PowerPoint や Googleスライドに書き出すと、書体が別のものに置き換わり、文字があふれることがあります。書き出した後のファイルで確かめます。
